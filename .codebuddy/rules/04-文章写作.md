# 文章写作规范

## 创建新文章

使用项目生成脚本（AI 创建与手动创建统一调用），自动生成文件名与 `id`：

```cmd
# 默认创建草稿（draft: true），写完后手动改为 false
powershell -ExecutionPolicy Bypass -File scripts\new-post.ps1 -Title "文章标题"

# 直接发布（draft: false）
powershell -ExecutionPolicy Bypass -File scripts\new-post.ps1 -Title "文章标题" -Published
```

### 文件命名与 id

- 文件名格式：`{type}_{rand5}_{ts}.md`，示例 `post_k7m2x_1764422400.md`
  - `type`：固定值，posts 目录 → `post`，about 目录 → `about`，其他 content 子目录按目录语义取短名
  - `rand5`：5 位 base36 随机串（小写字母 + 数字），保证同一时间戳下不重复
  - `ts`：创建时间的 Unix 时间戳（秒）
- `id` 字段 = 文件名去掉 `.md`，与文件名完全一致（如 `post_k7m2x_1764422400`），脚本自动写入，**不要手改**
- 文件名即 URL：文章链接为 `https://ptw-cwl.github.io/posts/{id}/`，中文标题仅在页面内展示
- **不要用中文/语义名作为文件名**（易重复、URL 含编码字符）
- 新增 content 目录时，需同时在 `hugo.toml` 的 `[params] loadSections` 与 `scripts/new-post.ps1` 的 `$sectionMap` 登记，否则不渲染/无法生成

### about 单页特殊说明

- about 是单页，文件名固定为 `content/about/index.md`（URL 固定 `/about/`），不参与随机命名
- `id` 格式同为 `about_{rand5}_{ts}`，已手动写入 front matter；脚本 `-Type about` 时只提示补 id，不覆盖已有文件

创建后按下方字段顺序检查并补全 front matter。

## front matter 规范

```yaml
---
title: "文章标题"
id: post_k7m2x_1764422400
createTime: 2026-08-15 14:30:00
updateTime: 2026-08-15 14:30:00
tags: ["notes", "hugo"]
description: "50-100 字的一句话摘要"
draft: false
---
```

- 字段顺序固定：`title` → `id` → `createTime` → `updateTime` → `tags` → `description` → `draft`
- `title`：中文标题加引号
- `id`：文件唯一标识，与文件名一致（见上文「文件命名与 id」），生成脚本自动写入；手工创建文章时也须按同规则生成并填写
- `createTime`：创建时间，格式 `YYYY-MM-DD HH:MM:SS`（本地时间）
- `updateTime`：更新时间，与 `createTime` 同格式；新文章首次发布时与 `createTime` 相同，内容修订后改为修订时的完整时间
- 字段名由 `hugo.toml` 的 `[frontmatter]` 映射到 Hugo 标准 `date`/`lastmod`（排序、RSS 依赖标准字段，映射不可删），命名规范见 `02-编码规范.md`
- 模板取值与 front matter 对应：详情页用 `.Params.createTime` / `.Params.updateTime`（缺失时回退 `.Date` / `.Lastmod`），不要改回 `.Date` 直取
- `tags`：2-5 个为宜，使用**英文短码**（如 `notes`、`ai-tool`、`hugo`），中文显示名在 `data/tag_display.yaml` 登记，URL 用原生英文短码（如 `/tags/notes/`）；新增标签须先在映射文件登记再使用（见下文「标签与路径」）
- `description`：一句话摘要，**建议 50-100 字，硬上限 120 个汉字**，超出会被截断。用于搜索引擎 `<meta name="description">` 与首页/列表摘要；不填则回退站点级描述（`hugo.toml` 的 `[params] description`）。用中文自然语句概括文章主题与要点，避免堆砌关键词
- `draft`：写作中设为 `true`（不会部署线上），完成后改为 `false`
- `content/about/index.md` 等单页无需 `tags`、`description`

## 标签与路径

- 标签聚合页路径**不允许出现中文**（中文会被 percent 编码成 `/tags/%E9%9A%8F%E7%AC%94/`），统一改为**英文短码**作为 path，中文仅作渲染显示名
- 文章 `tags` 字段直接写英文短码（如 `notes`、`ai-tool`、`hugo`），URL 天然干净（`/tags/notes/`），无需在文章里写中文或 slug
- 中文显示名通过 `data/tag_display.yaml` 映射，模板渲染时查表展示（标签页大标题、SEO `<title>`、文章标签链接均走此映射）；映射 key 必须全小写，命名规则见 `02-编码规范.md`
- 新增标签流程：
  1. 先在 `data/tag_display.yaml` 登记短码与中文名（如 `notes: "随笔"`）
  2. 再在文章 `tags: ["notes"]` 使用
  3. 未登记的标签会导致 `scripts/check-tags.ps1` 校验失败（`exit 1`），构建前应修复
- **注意**：不再手写 `content/tags/<标签>/_index.md`，标签 term 页由 Hugo taxonomy 自动生成

## 内容加载白名单

- `hugo.toml` 的 `[params] loadSections` 控制 `content/` 下哪些子目录被渲染展示，默认 `['posts', 'about']`
- 未登记的目录：首页最新文章、section 列表页、文章详情页均不渲染（模板层控制），标签聚合页只统计已登记目录的文章
- 新建内容目录（如 `notes/`）后，先在 `loadSections` 登记才能上线展示
- **硬约束：仓库内不得残留未登记在 `loadSections` 的 `content/` 子目录**。临时测试目录（如 `content/notes/test.md` 这类空文件或试验目录）用后必须删除，禁止作为半成品残留在仓库，否则会被误认为正式分类、污染构建与标签校验范围

## 作者与时间的显示

- 文章详情页、列表页、首页自动显示**作者 + 创建时间 + 更新时间**，由模板渲染，无需在正文书写
- 详情页显示为「作者 · 创建于 `YYYY-MM-DD HH:MM:SS` · 更新于 `YYYY-MM-DD HH:MM:SS`」；列表页/首页显示「作者 · `YYYY-MM-DD HH:MM:SS`」
- 作者名统一取 `hugo.toml` 的 `[params] author`（当前为"言黎"），不要写死在正文里
- 更新时间仅在 `updateTime` 晚于 `createTime` 时显示（模板已处理），因此修订文章时记得同步更新 `updateTime`

## 正文结构

- 开头 1-2 句点明文章主题（作为摘要展示）
- 使用 `##` 划分章节，标题层级规范，不跳级（`##` 后接 `###`，不用 `#` 做主标题）
- **开头与正文对应**：开头列举的内容（数量、顺序）必须与正文章节一一对应。如开头写"踩了三个坑"，正文就按「坑一 / 坑二 / 坑三」编号逐一展开，禁止开头提三个、正文只写两个这类前后不搭
- **编号统一**：踩坑/清单类章节用「坑一」「坑二」连续编号，标题直接点出坑是什么（如"坑二：PATH 里加的是文件不是目录"），方便扫读定位
- **命名与内容一致**：文件名、标题要贴合正文主体。内容以踩坑为主就命名为"XX 踩坑记"，不要用与内容无关的泛化标题
- 列表、代码块等保持合理留白；代码块必须标注语言（```go / ```html / ```css / ```bash）
- 链接使用 Markdown 标准写法；站内文章链接优先用相对路径或 `.RelPermalink`

## 图片处理

- 图片放入 `static/images/`（该目录如不存在则创建），正文引用：

```markdown
![图片说明](/images/文件名.png)
```

- 图片命名使用英文小写 + 连字符（如 `hugo-arch.png`），尺寸尽量压缩（建议 < 500KB）

## 发布流程

1. 写作完成，`draft` 改为 `false`
2. 标签校验：运行 `powershell -ExecutionPolicy Bypass -File scripts\check-tags.ps1`，确认所有标签已在 `data/tag_display.yaml` 登记且 key 为小写（失败则 `exit 1`）
3. 本地预览验证：`D:\app\hugo_0.165.0_windows-amd64\hugo.exe server -D`（访问 http://localhost:1313/）
4. 确认渲染正常（标题、标签链接、代码高亮、暗色模式）后，提交信息使用 `feat: 新增文章《xxx》`（见 `02-编码规范.md` 提交规范）
5. 推送后 GitHub Actions 自动部署，访问线上地址验证

语言表达风格（语气、用词、句式）详见 `05-写作风格.md`。
