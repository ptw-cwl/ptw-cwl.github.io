# 敏感信息保护（工程与内容共用）

> 本规则为强制红线，优先级高于其他规则。任何涉及 GitHub Actions 等凭证使用的场景都必须遵守。

## 禁止入库的敏感信息

以下任何一类**严禁**写入仓库中可被提交的文件（包括但不限于：`content/**`、`scripts/**`、`hugo.toml`、`data/**`、`.github/**`、任何 `.md` / `.ps1` / `.yml` / `.toml` / `.env`）：

- 账号、密码、口令
- API Key / Secret / AppKey / AppSecret
- Cookie、Session、登录态、Token（含 access token / refresh token / JWT）
- 私有的 Webhook 地址、带凭证的 URL
- 数据库连接串、内网地址与端口

## 凭证的正确存放方式

- 一律走**本地环境变量**，发布脚本从 `env:` 读取（如 `$env:BJH_COOKIE`、`$env:BJH_TOKEN`）
- 或放在**被 `.gitignore` 忽略的本地文件**（如 `scripts/.secrets.local.ps1`），该文件只定义变量、不入库
- CI（GitHub Actions）中用 **Repository Secrets**，绝不在 workflow 文件里硬编码

## 强制约束

- 新增/修改脚本、配置文件时，若需凭证，只能引用环境变量或本地忽略文件，**不得出现明文凭证**
- 提交前若发现误写了凭证：立即从文件删除，**并视为泄漏**，尽快在对应平台吊销/重置该凭证，再提交
- 本仓库 `.gitignore` 已忽略 `scripts/.secrets.local.ps1` 等本地凭证文件，新增本地凭证文件须同步加入 `.gitignore`

## 自检

- 提交前在本地确认没有把凭证写进会提交的脚本/文章/配置文件
