# 编码规范

## 通用

- 注释一律使用中文；**所有文本源文件（`.ps1` / `.md` / `.html` / `.css` / `.yaml` / `.toml`）保存为 UTF-8 无 BOM 编码**，避免中文乱码
- **编码坑位（重点）**：PowerShell 脚本（`.ps1`）若被保存为系统默认 ANSI/GBK 编码，中文注释与字符串在运行时会被解析成乱码并报 `字符串缺少终止符` 等错误。写入/生成 `.ps1` 时必须以 UTF-8 落盘（如 `Out-File/Set-Content/Add-Content -Encoding utf8`），不要用工具默认的 GBK 写入；含内嵌转义引号的中文行易触发解析错误，尽量改写为无嵌套转义引号的写法
- 修改已有代码前，先理解原有逻辑，在其基础上小步修改，不要整体重写或移除原有功能
- 生成内容时使用与现有代码一致的风格（缩进、命名、引号）

## Go 模板（layouts/）

- 只使用 Hugo 内置函数，不引入自定义模板函数
- 导航高亮必须使用 Hugo 标准方法：`IsMenuCurrent` / `HasMenuCurrent`，不要手写 URL 字符串比较
- 标签链接统一用 `site.GetPage (printf "/tags/%s" $tag)` 反查页面对象，**不要手动拼接 URL**；标签用 `data/tag_display.yaml` 映射中文显示名，URL 用原生英文短码（如 `/tags/notes/`），mapping key 一律小写，登记规则见 `04-文章写作.md`
- 文章上下页导航用 `.PrevInSection` / `.NextInSection`，并用 `if or .PrevInSection .NextInSection` 包裹，避免空白导航区域
- 内部链接使用 `relLangURL` 处理相对/绝对路径
- 不要使用已废弃的配置项（如 `languageCode`，应使用 `locale`）

## 样式（assets/css/style.css）

- 使用 CSS 变量（`:root` 与暗色模式媒体查询），颜色、间距等值优先走变量
- 新增组件样式遵循现有命名与缩进风格（2 空格缩进）
- 保持亮/暗双模式可用，新增颜色必须同时提供两种模式的值

## 命名规范

- front matter 时间字段使用驼峰式：`createTime`（创建时间）/ `updateTime`（更新时间），由 `hugo.toml` 的 `[frontmatter]` 映射到 Hugo 标准 `date`/`lastmod`，不要在文章里写 `date`/`lastmod` 或中文名
- 自定义 front matter 字段一律 camelCase（如 `createTime`、`updateTime`），不使用中文键名、不用 snake_case / kebab-case
- `hugo.toml` 配置键使用 Hugo 标准键名（如 `baseURL`、`pageRef`），不自定义别名
- 模板内变量使用 camelCase（如 `$post`、`$tag`），与 Hugo 内置风格一致
- 图片命名英文小写 + 连字符（如 `hugo-arch.png`），见 `04-文章写作.md`
- 文章文件名与 `id` 字段遵循 `{type}_{rand5}_{ts}` 规范（如 `post_k7m2x_1764422400`），生成脚本见 `04-文章写作.md`
- 标签短码（`data/tag_display.yaml` 的 key 及文章 `tags` 字段）使用英文小写 + 连字符（如 `notes`、`ai-tool`），不用下划线或中文；中文显示名在 `data/tag_display.yaml` 登记

## 提交规范（Conventional Commits）

- 提交信息格式与 Git 安全约束见用户级规则 `02-通用提交规范.md`（跨项目生效），本项目不重复书写
- 本项目专属约束：
  - 不要提交 `public/`、`resources/`、`.hugo_build.lock` 等被忽略的构建产物（`.codebuddy/rules/` 为共享规则，需正常提交）
  - 提交示例：`feat: 新增 xxx 文章`、`chore: 清理无用目录`

文章写作规范详见 `04-文章写作.md`。
