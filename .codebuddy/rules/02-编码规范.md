# 编码规范

## 通用

- **所有文本源文件（`.ps1` / `.md` / `.html` / `.css` / `.yaml` / `.toml`）保存为 UTF-8 无 BOM 编码**，避免中文乱码
- 修改已有代码前，先理解原有逻辑，在其基础上小步修改，不要整体重写或移除原有功能
- 生成内容时使用与现有代码一致的风格（缩进、命名、引号）

## PowerShell 脚本编码约束（方案 A）

> 本站约定：`.ps1` 脚本一律采用**方案 A**——脚本文件（含代码、字符串字面量、注释、运行期输出）**全部 ASCII 字符**，不出现任何中文。文件仍以 UTF-8 无 BOM 存储（符合通用规则）。详见下方「为什么」。

- **为什么必须全 ASCII**：Windows 自带 `powershell.exe`（5.1）加载 `.ps1` 时**默认按系统本地代码页 GBK/936 解码**。若文件含 UTF-8 中文（哪怕只在 `#` 注释里），多字节序列会被 GBK 拆坏，连带错位导致 `字符串缺少终止符`、`意外 }` 等解析错误。而 `pwsh`（PowerShell 7+）默认 UTF-8，但因本站未强制依赖 pwsh，故脚本须对 5.1 也安全 → 全 ASCII 是最稳方案。
- **允许中文的场景**：仅脚本**读取/生成的内容数据**可含中文（如 `new-post.ps1` 的 `-Title` 参数、它写入文章的 `title` 字段、生成的正文文件）。脚本自身的代码、注释、`Write-Host` 提示一律英文。
- **禁止**：给 `.ps1` 加 UTF-8 **BOM**（违背本站 UTF-8 无 BOM 规则，且 Hugo 解析 BOM 会异常）；改系统代码页；依赖 pwsh 专属语法。
- **写入/生成文件**：涉及 `.ps1` 落盘内容时用 UTF-8 无 BOM（如 `New-Object System.Text.UTF8Encoding($false)` 或 `Set-Content/Out-File -Encoding utf8`），不要用工具默认 GBK 写入。
- **含内嵌转义引号的中文行易触发解析错误**，即便未来放宽此约束也不应在脚本里写中文，当前按本规则全 ASCII 执行。
- **运行方式**：统一 `powershell -ExecutionPolicy Bypass -File scripts\xxx.ps1`，无需切换 pwsh。

## Go 模板（layouts/）

- 只使用 Hugo 内置函数，不引入自定义模板函数
- 导航高亮必须使用 Hugo 标准方法：`IsMenuCurrent` / `HasMenuCurrent`，不要手写 URL 字符串比较
- 标签链接统一用 `site.GetPage (printf "/tags/%s" $tag)` 反查页面对象，**不要手动拼接 URL**；标签用 `data/tag_display.yaml` 映射中文显示名，URL 用原生英文短码（如 `/tags/notes/`），mapping key 一律小写，登记规则见 `04-文章写作.md`
- 文章上下页导航用 `.PrevInSection` / `.NextInSection`，并用 `if or .PrevInSection .NextInSection` 包裹，避免空白导航区域
- 内部链接使用 `relLangURL` 处理相对/绝对路径
- 不要使用已废弃的配置项（如 `languageCode`，应使用 `locale`）
- **Hugo 版本相关 API 取舍（踩坑约定）**：
  - 读取 `data/` 下的数据文件统一用 `hugo.Data.xxx`（如标签中文名映射 `hugo.Data.tag_display`），**不要用 `site.Data`**——后者在 Hugo v0.156.0 起已弃用，构建会出 `deprecated` 警告
  - `block` 动作**不能内联赋值给变量**（如 `{{ $x := block "title" . }}...` 会报 `unexpected <block> in command`）；需要可覆盖的标题时，baseof 用 `{{ block "xxx" . }}` 输出，页面模板用 `{{ define "xxx" }}` 覆盖
  - **同名 `block` 在一个文件里只能出现一次**：多个元标签想复用同一覆盖值时，必须拆成不同的 block 名（如 `ogtitle` / `twtitle` 各定义一次），不能写两次同名 `block`
- **时间格式化固定用 Go 参考时间 `2006-01-02 15:04:05`**（年月日时分秒），不要写成 `YYYY-MM-DD HH:mm:ss` 等其它格式；详情页/列表页显示时间统一走该格式

## 样式（assets/css/style.css）

- 使用 CSS 变量（`:root` 与暗色模式媒体查询），颜色、间距等值优先走变量
- 新增组件样式遵循现有命名与缩进风格（2 空格缩进）
- 保持亮/暗双模式可用，新增颜色必须同时提供两种模式的值

## 命名规范

- front matter 时间字段使用驼峰式：`createTime`（创建时间）/ `updateTime`（更新时间），由 `hugo.toml` 的 `[frontmatter]` 映射到 Hugo 标准 `date`/`lastmod`，不要在文章里写 `date`/`lastmod` 或中文名
- 自定义 front matter 字段一律 camelCase（如 `createTime`、`updateTime`），不使用中文键名、不用 snake_case / kebab-case
- `hugo.toml` 配置键使用 Hugo 标准键名（如 `baseURL`、`pageRef`），不自定义别名
- 模板内变量使用 camelCase（如 `$post`、`$tag`），与 Hugo 内置风格一致
- 图片命名英文小写 + 连字符（如 `hugo-arch.png`），见 `04-文章写作.md`
- 文章文件名与 `id` 字段遵循 `{type}_{rand5}_{ts}` 规范（如 `post_k7m2x_1764422400`），生成脚本见 `04-文章写作.md`
- 标签短码（`data/tag_display.yaml` 的 key 及文章 `tags` 字段）使用英文小写 + 连字符（如 `notes`、`ai-tool`），不用下划线或中文；中文显示名在 `data/tag_display.yaml` 登记

## 提交规范（Conventional Commits）

- 提交信息格式与 Git 安全约束见用户级规则 `02-通用提交规范.md`（跨项目生效），本项目不重复书写
- 本项目专属约束：
  - 不要提交 `public/`、`resources/`、`.hugo_build.lock` 等被忽略的构建产物（`.codebuddy/rules/` 为共享规则，需正常提交）
  - 提交示例：`feat: 新增 xxx 文章`、`chore: 清理无用目录`

文章写作规范详见 `04-文章写作.md`。
