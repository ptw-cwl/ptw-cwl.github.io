# CodeBuddy 规则索引

本目录为项目 CodeBuddy 规则，按**领域主题**分类。所有规则对 AI 编码行为生效。

## 分类总览

| 编号 | 文件 | 领域 | 职责边界 |
|------|------|------|----------|
| 01 | 项目概述 | 项目信息 | 技术栈 / 目录结构 / 常用命令 / 关键约定 |
| 02 | 编码规范 | 代码书写 | Go 模板 / CSS / front matter / 命名规范 / 注释 / 提交信息 |
| 03 | 构建与部署 | 工程规范 | GitHub Actions / Pages 设置 / 发布流程 |
| 04 | 文章写作 | 内容创作 | 新文章 front matter（createTime/updateTime）/ 作者与时间显示 / 正文结构 / 图片 / 草稿流程 |
| 05 | 写作风格 | 内容创作 | 去 AI 味 / 语气 / 用词 / 句式 / 篇幅 / 示例反例 |
| 06 | 内容合规 | 内容创作 | 本站定位 / 素材版权 / 隐私 / AI 声明 / 时效性 |

## 划分原则

- **一个职责一条规则**：每个文件只负责一个主题，发现一个文件包含两个独立主题时拆分，新主题取该领域下一个编号。
- **同一主题只在一处定义**：规则间交叉内容只引用编号（如"详见 `01-项目概述.md`"），不重复展开，避免内容重复维护。

## 新增规则的归类原则

后续新增规则直接取下一个编号，并登记到"分类总览"表格：

| 领域 | 现有文件 |
|------|----------|
| 项目信息 | 01-项目概述 |
| 代码书写 | 02-编码规范 |
| 工程规范 | 03-构建与部署 |
| 内容创作 | 04-文章写作、05-写作风格、06-内容合规 |

新增规则时**在"分类总览"表格中登记一行**，并在文件开头标注所属领域，保持索引与文件一致。

## 规则间引用约定

- 规则文件相互引用使用相对文件名（如"详见 `02-编码规范.md`"），不要重复展开另一条规则的内容，只引用编号。
- 同一主题只在一个文件中定义，其他文件引用，禁止多处重复书写。
