# 构建与部署规范

## GitHub Pages 部署方式

- 本项目使用 GitHub Actions 自动部署，唯一部署配置文件为 `.github/workflows/hugo-deploy.yml`
- 仓库 Settings → Pages → Source 必须选择 **GitHub Actions**，否则不会触发发布
- 不要新增其他 workflow 文件（例如 GitHub 引导自动生成的 `static.yml`，它会发布源码而非 `public/` 构建产物，导致站点无法访问）

## workflow 关键约束

- 保留 `hugo-deploy.yml` 中已有逻辑：
  1. 下载安装 Hugo Extended v0.165.0（`hugo_extended_${HUGO_VERSION}_linux-amd64.tar.gz`）
  2. `actions/configure-pages@v5` 初始化 Pages
  3. `hugo --gc --minify --baseURL ...` 构建
  4. `actions/upload-pages-artifact@v3` 上传 `./public`
  5. `actions/deploy-pages@v4` 发布
- 使用与仓库一致的 Hugo 版本（v0.165.0）与 Extended 版本（构建 CSS 需要）
- 修改 workflow 前先理解现有步骤，仅做必要调整

## 本地构建前清理 public/

- `hugo --gc --minify` 的 `--gc` **只清理 Hugo 内部资源缓存，不清理 `public/` 的孤儿目录**。当页面路径变更（如标签由 `/tags/随笔/` 改为 `/tags/suibi/`）后，旧目录（如 `public/tags/随笔/`）不会被自动删除，会作为脏产物残留。线上 GitHub Actions 是全新构建不受影响，但本地 `public/` 需手动保持干净
- **本地构建标准动作**：先删空 `public/` 再构建，确保输出是干净的：

```cmd
# 先清理旧构建产物（含路径变更后残留的孤儿目录），再构建
rmdir /s /q public
D:\app\hugo_0.165.0_windows-amd64\hugo.exe --gc --minify
```

- `public/`、`resources/`、`.hugo_build.lock` 已被 `.gitignore` 忽略，删除 `public/` 不会丢失任何需提交的内容，可放心清空
- 禁忌：不要手动修改/提交 `public/` 下的文件

## 代码高亮

- 文章代码块语法高亮使用 Hugo 内置 **Chroma**（`hugo.toml` 的 `[markup.highlight]` 已配置 `noClasses = false`，配色由 `assets/css/style.css` 中的 `.chroma` / `.highlight` 类提供）
- **禁止在模板中引入外部 highlight.js / Prism 等 JS 或 CDN**（与本站"纯静态、无前端框架、无外部依赖"的定位冲突），配色一律走 CSS 内置方案
- 切换高亮配色时只改 `assets/css/style.css` 的 `.chroma` token 颜色，勿在模板加 `<script>`
- 代码块复制按钮允许使用**内联原生 JS**（见 `layouts/_default/baseof.html`），同样**禁止引入外部 clipboard.js 等库或 CDN**；复制逻辑仅作用于 `.highlight > pre` 文本

## SEO 与站点元数据

本站 SEO 元数据集中在 `layouts/_default/baseof.html` 的 `<head>` 统一输出，各页面模板通过 `block` 覆盖标题。

### 已实现的 SEO 项

- **canonical**：`<link rel="canonical" href="{{ .Permalink }}">`，所有页面输出，避免重复内容
- **Open Graph**：`og:type`（`article` / `website`）、`og:title`、`og:description`、`og:url`、`og:site_name`、`og:locale=zh_CN`
- **Twitter Card**：`twitter:card=summary`、`twitter:title`、`twitter:description`
- **描述优先级**：文章/页面优先取自己的 `description`（front matter），缺失回退站点描述 `params.description`
- **`robots.txt`**：`static/robots.txt` 静态文件，全站 `Allow: /` 并引用 `sitemap.xml`（Hugo 默认生成 `public/sitemap.xml`，无需额外配置）
- **标签页标题中文化**：`terms.html`（标签总页）固定 `<title>`=标签、`<h1>`=标签；`list.html` 中单个标签页（`Kind == "term"`）通过 `hugo.Data.tag_display` 查表显示中文，`default .Data.Term` 兜底，未登记标签也不会让 `<title>` 空白

### 标题 block 约定（重要）

- baseof 用 `{{ block "title" . }}`、`{{ block "ogtitle" . }}`、`{{ block "twtitle" . }}` 三个独立 block，**同名 block 在一个文件只能出现一次**，页面模板用 `{{ define "xxx" }}` 覆盖
- 不要在 baseof 中把 `block` 内联赋值给变量（如 `{{ $x := block "..." }}`，Hugo 不支持，会报 `unexpected <block> in command`）
- `twitter:title` 不能复用 `ogtitle` 同名 block，必须单独用 `twtitle` block 并在需要自定义标题的页面（terms/list 的 term 分支）一并 `define`

### 标签查表写法

- 查表统一用 `hugo.Data.tag_display`（不要写成 `site.Data`，该写法在 Hugo v0.156+ 已弃用会出警告）

### 可选增强（暂未做）

- JSON-LD 结构化数据（`BlogPosting`）：按用户决定「有封面图才带、没图不带」，**当前文章无封面字段故暂不实现**；将来若引入 `cover` front matter 字段再加
- `og:image` / 分享封面图：同上，待有封面字段后再补

## 发布流程

1. 本地执行清理式构建（先 `rmdir /s /q public` 再 `hugo --gc --minify`，见上文「本地构建前清理 public/」）确认零报错零警告
2. 提交并推送 `main` 分支
3. 等待 GitHub Actions 运行完成，通过 `https://ptw-cwl.github.io/` 验证线上效果
4. 验证项：首页、文章页、关于页、RSS、标签中文显示名正常且英文路径正确
5. SEO 抽查项（改完 head/模板后必查）：
   - `public/tags/index.html` 的 `<title>`=标签…、`<h1>`=标签
   - `public/tags/<某标签>/index.html` 的 `<title>`=中文标签名（不再空白）
   - 文章页 `<meta name="description">` 为文章自身描述（非站点描述）；含 `canonical`/`og:`/`twitter:` 标签
   - `public/robots.txt` 存在且内容正确、`public/sitemap.xml` 存在
